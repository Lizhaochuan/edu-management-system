# 教务 / 课时管理系统

本仓库用于 **5 个 Antigravity 账号按 A → B → C → D → E → A 严格轮流接力开发** 同一套教育管理系统。包含微信小程序、Web 管理端与 Node.js 后端。

## 项目目录
- `pages/`、`components/`：微信小程序。
- `web-admin/`：Web 管理端。
- `server.js`、`services/`：后端业务代码。
- `data/db.json`：正式业务数据，**不得上传 GitHub**。

## 分支约定
- `main`：稳定代码基线，不用于日常开发。
- `work`：5 个账号按顺序接力的开发分支；**任何时候只有一个 Agent 可以写入**。
- 每次交班必须成功推送 `work` 的全部需要保留的改动并写清交接内容；接班人先读取 `work` 最新提交。
- 一个任务完成并验收后，再通过 Pull Request 将 `work` 合并到 `main`；合并后先使 `work` 跟上 `main`。
- 可在后续改成每任务一个分支，但不能同时启用互相冲突的交接流程。

## 安全规则
- 不上传 `data/db.json`、个人信息、`.env`、密码、令牌、密钥和本地私有配置。
- 不在云端 Agent 中使用正式数据库进行开发测试；应使用隔离的测试数据。
- 正式后端和数据库保持单一写入来源，不能依靠网盘同步活跃数据库。
- `.gitignore` 不能替代人工安全检查；推送前必须审核暂存文件。
- 历史代码不代表 Notion 的最新需求已全部实现。

首次开发请先读 [HANDOFF.md](HANDOFF.md)。任何 Agent 不得在没有最新交接上下文时自行继续编程。
